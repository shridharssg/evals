====================================================================
THREE LEVELS OF EVALUATION
====================================================================

1. Component Level
2. Pipeline Level
3. Application/System Level


####################################################################
# LEVEL 1: COMPONENT EVALUATION
####################################################################

STEP 1: BUILD THE RETRIEVER

Tasks:

• Load documents
• Perform chunking
• Generate embeddings
• Store vectors
• Retrieve relevant chunks


--------------------------------------------------------------------
STEP 2: EVALUATE THE RETRIEVER
--------------------------------------------------------------------

Metrics:

1. Recall

Measures:
"Out of all relevant documents, how many did the retriever retrieve?"

2. Precision

Measures:
"Out of all retrieved documents, how many are actually useful?"


--------------------------------------------------------------------
STEP 3: BUILD THE GENERATOR
--------------------------------------------------------------------

Input:
• Question
• Context

Output:
• Answer


--------------------------------------------------------------------
STEP 4: EVALUATE THE GENERATOR
--------------------------------------------------------------------

Metrics:

1. Faithfulness

Checks whether the answer is generated strictly from
provided context and not hallucinated.

2. Relevance

Checks whether the generated answer is relevant
to the user's question.

3. Citation Accuracy

Checks whether references to documents,
transcripts, or lecture sources are correct.


####################################################################
# LEVEL 2: PIPELINE EVALUATION
####################################################################

STEP 5: BUILD THE RAG PIPELINE

Retriever + Generator


--------------------------------------------------------------------
STEP 6: EVALUATE THE RAG PIPELINE
--------------------------------------------------------------------

RAG TRIAD

Three key metrics:

1. Context Relevance

Question <--> Context

Checks:
Did the retriever fetch the correct context?


2. Faithfulness

Answer <--> Context

Checks:
Was the answer generated from the context?


3. Answer Relevance

Question <--> Answer

Checks:
Did the answer actually answer the question?


####################################################################
# LEVEL 3: APPLICATION EVALUATION
####################################################################

APPLICATION QUALITY METRICS

1. Correctness

Checks whether the answer is factually correct.


2. Completeness

Checks whether all parts of the question were answered.


3. Style

Checks whether the chatbot's explanation style matches
CampusX teaching style.

EVALUATION SUITE (EVAL SUITE)
====================================================================

An Eval Suite is a collection of tests that evaluate:

• Components
• Pipelines
• Applications
• Safety
• Operations

All tests together give a complete picture of system quality.

REGRESSION TESTING
====================================================================

Purpose:

Verify whether Version 2 is better than Version 1.


Suggested Project Structure:

Project
|
+-- src
|   +-- retriever.py
|   +-- generator.py
|   +-- rag_pipeline.py
|
+-- evals
|   +-- eval_retriever.py
|   +-- eval_generator.py
|   +-- eval_pipeline.py
|   +-- eval_safety.py
|   +-- eval_ops.py
|
+-- run_evals.py


Running:

python run_evals.py

This executes every evaluation and generates a report.

INTERVIEW ANSWER:
HOW DO YOU EVALUATE A RAG CHATBOT?
====================================================================

1. Evaluate Components
   • Retriever -> Precision, Recall
   • Generator -> Faithfulness, Relevance

2. Evaluate Pipeline
   • Context Relevance
   • Faithfulness
   • Answer Relevance

3. Evaluate Application
   • Correctness
   • Completeness
   • Style
   • Safety
   • Operational Metrics

4. Build an Eval Suite

5. Run Regression Testing

6. Deploy Only After Passing Evaluation Thresholds

7. Run Online Evaluations After Deployment

8. Add Real-World Failures Back Into Evaluation Datasets
